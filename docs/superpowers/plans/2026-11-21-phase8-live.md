# Phase 8 – Liveticker und Spielbericht: Implementation Plan

**Goal:** A live ticker for every running Bundesliga match (score, minute, goals, cards, substitutions, live stats, momentum), and right after the final whistle the full match statistics plus refreshed table, team stats, predictions, scouting and player values.

**Architecture (no own server):**
- New workflow `live.yml`: every 5 minutes on match days (Fri–Mon 12–22 UTC). `live.py` finds matches between kick-off and kick-off + 2 h 30, fetches their FotMob pages, writes `data/live/<oldb id>.json` + `data/live/index.json`, commits only `data/live`. When a match has just ended it starts `data.yml` (`gh workflow run`), so statistics, table and everything derived are updated within minutes instead of the next hourly run.
- The app reads live files through the GitHub contents API (`api.github.com/repos/<repo>/contents/data/live/...`, CORS allowed, no CDN delay) while a match is running, polling every 60 s; score and goals additionally straight from OpenLigaDB if it allows browser access (checked in the exploration run). Without network the app shows the last state.
- Delay honestly stated in the app: FotMob details about 5–10 minutes (GitHub schedule), goals/score from OpenLigaDB about 1 minute.

**Match report after the final whistle** (finished match page, additions to the existing analysis): events timeline (goals, assists, cards, substitutions), xG timeline (cumulative xG per minute from the shot map), player table (minutes, rating, goals, assists, xG, xA, shots, key passes, box touches, tackles, interceptions, duels).

## Tasks

2. `live.py` + `live.yml` (+ dispatch of `data.yml` when a match finishes); tests with fake fetcher and clock.
3. App: live card on match day list, live view on the match page with polling, "LIVE" tab badge; match report additions; tests.
4. Verify on today's real matches (15:30 and 18:30 kick-offs), review, PR, merge.
